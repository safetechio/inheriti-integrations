# Create and inspect plans

`inheriti plans create [--title NAME] [--description TEXT] [--asset TYPE ...]` passes **editable, non-secret hints** to the local plan assistant. Preserve title and description supplied in the user's request; use exact catalog IDs from `inheriti help plans create` for asset hints (for example, `--asset API-KEY`, not `--asset "API key"`). Do not put a password, recovery phrase, private key, token, or protected file contents in these options or in plan metadata. If the request already contains a secret-like value, do not repeat it or ask for another value in chat; tell the person to enter it only in the secure window.

Creation requires sign-in, a selected Inheriti Business Organisation, an interactive terminal, a desktop window, and a claimed Organisation Key for that member. On first use, the CLI may offer to download its local assistant runtime and model (about 1.1 GB). The person enters protected content in the secure window, edits the draft, confirms creation, and may need to release the Organisation Key in SafeKey Mobile. Let the CLI present its progress. Report the plan ID and status returned by the CLI; do not claim completion while it is pending.

`inheriti plans list` finds safe plan metadata, `inheriti plans show PLAN_ID` shows assets, fields, participants and policy, and `inheriti plans logs PLAN_ID` shows activity. Use these for verification and context, not as sources of protected values. For a request such as “create a plan called Family Archive with description Documents for my brother,” run the create command with those two hints, then hand off to the secure window. If the user requests an unsupported asset or omits important non-secret structure, explain the available choices rather than inventing one.
